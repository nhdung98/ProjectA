# Protocol 3 member submissions

Submit the original result ZIP and terminal LOG generated by the command. No
manual metric calculation, CSV editing or archive creation is needed.

Folders are prepared for each member and round:

```text
roundA/member1/ ... roundA/member4/
roundB/member1/ ... roundB/member4/
```

After running, copy the two files whose paths the terminal printed into your
assigned folder. Keep their generated names. Preserve failed runs for diagnosis;
the ZIP summary distinguishes failed runs from complete results.

For example, member 1 submits round A from the repository root:

```powershell
git switch -c results/member1-roundA
Copy-Item -LiteralPath '<exact ZIP path printed in terminal>' -Destination submissions/protocol3/roundA/member1/
Copy-Item -LiteralPath '<exact LOG path printed in terminal>' -Destination submissions/protocol3/roundA/member1/
git add submissions/protocol3/roundA/member1/
git commit -m "Submit member 1 round A results and log"
git push -u origin results/member1-roundA
```

Replace the two placeholder paths with the actual paths, and change member/round
as assigned. If that result branch already exists locally, use `git switch`
without `-c`. Submit on your own results branch; keep the shared experiment code
unchanged. Tell the leader the branch name after pushing. Creating folders does
not enable automatic uploading; these push commands transfer the files.

For round B, first follow the existing frozen-release instructions. Do not start
round B simply because its submission folders exist. Large archives may require
another transfer method if GitHub rejects their size.
